# Indico Pen Spike Implementation Plan

## Summary

Build a regular C# WinUI 3 desktop app from the spec in `docs/2026-06-02 - Spec.md`. The app will load local PDFs, render pages in a vertical scroll view, overlay native WinUI ink canvases per page, support pen/mouse drawing, touch scrolling, erasing, undo/redo, stroke counting, and pointer diagnostics.

Interpret “create me” as `README.md`, and also add `AGENTS.md` and `ARCHITECTURE.md`.

## Key Changes

### 1. Scaffold The Solution

- Create a C# WinUI 3 desktop app solution named `PdfScannerWinUI3` or `IndicoPenSpike`.
- Use a normal packaged WinUI 3 desktop app targeting Windows 10/11.
- Add projects:
  - `src/IndicoPenSpike/` for the WinUI app.
  - `tests/IndicoPenSpike.Tests/` for unit tests.
- Use Windows App SDK / WinUI 3 tooling from Visual Studio if `dotnet new winui` is unavailable locally.
- Add solution-level files:
  - `README.md`
  - `AGENTS.md`
  - `ARCHITECTURE.md`

### 2. App Shell And Layout

- Implement `MainWindow` with title `Indico Pen Spike`.
- Use a vertical layout:
  - Menu bar: `File`, `Edit`, `View`, `Window`, `Help`.
  - Toolbar row.
  - Scrollable document area.
- Only `File > Open PDF` and toolbar `Open PDF` need behavior.
- Empty state centered in the document area:

  ```text
  PDF Pen Spike

  Open a local PDF, then try pen input, erasing, undo, redo, palm rejection,
  and scrolling.
  ```

- Toolbar controls:
  - `Open PDF`
  - active tool indicator: `Ink` / `Eraser`
  - pointer mode indicator: `No pointer input yet`, `Mouse`, `Pen`, `Touch`, `Eraser`
  - `Undo`
  - `Redo`
  - stroke count
  - debug status text

### 3. PDF Loading And Rendering

- Use `FileOpenPicker` initialized with the WinUI window handle.
- Accept `.pdf` files only.
- Use `Windows.Data.Pdf.PdfDocument.LoadFromFileAsync`.
- Render each page with `PdfPage.RenderToStreamAsync`.
- Convert rendered page streams into `BitmapImage` or another WinUI-compatible image source.
- Render pages vertically inside a `ScrollViewer`.
- For each rendered page, create a page view containing:
  - filename shown once above page 1
  - optional page number/debug label
  - rendered PDF page image
  - annotation layer directly over the image
- Preserve PDF page aspect ratio.
- Use a fixed render width cap, for example `1600px`, to keep 100-page PDFs practical for the spike.
- Page background should be white; document background should be light gray with visible page padding.

### 4. Annotation Model

- Store annotations in page-relative coordinates.
- Add core model types:
  - `AnnotationStroke`
    - `Guid Id`
    - `int PageNumber`
    - `IReadOnlyList<StrokePoint> Points`
    - `Color Color`
    - `double Thickness`
    - `string InputType`
  - `StrokePoint`
    - `double X`
    - `double Y`
    - optional `double Pressure`
  - `AnnotationDocument`
    - filename
    - page count
    - strokes grouped by page
- Black ink only.
- Fixed default thickness.
- No persistence to disk required.

### 5. Ink Layer

- Use native WinUI `InkCanvas`/`InkPresenter` per PDF page rather than a custom-only pointer drawing layer.
- Configure ink to support pen and optional mouse drawing.
- Prefer native ink behavior for palm rejection.
- Touch should scroll and should not create ink strokes.
- Maintain one annotation/ink layer per page so stroke-page association is unambiguous.
- When strokes are collected, copy their points into the app’s page-relative `AnnotationDocument`.
- Keep native ink strokes visible on the page after completion.

### 6. Tool Modes And Cursor Feedback

- Add two explicit modes:
  - Ink mode
  - Eraser mode
- Toolbar should show current mode.
- In ink mode:
  - mouse cursor should be crosshair when over a page if practical.
  - pen hover should update pointer status to `pen` when WinUI exposes it.
- In eraser mode:
  - cursor should visibly differ from ink mode, such as square/circle/crosshair fallback.
  - tapping or crossing a stroke removes it.
- Attempt inverted stylus eraser support:
  - detect eraser-capable pointer/ink events where WinUI exposes them.
  - automatically switch to erasing behavior for that input event/session if possible.
  - always update debug text so the hardware behavior can be evaluated.

### 7. Erasing

- Minimum acceptable eraser behavior:
  - switch to eraser mode.
  - crossing/tapping a stroke removes it.
- Prefer native `InkPresenter` erasing mode if it provides reliable full-stroke erasing.
- If native erase produces partial stroke edits, treat that as acceptable for the spike, but keep the model synchronized by rebuilding page strokes from the `InkPresenter.StrokeContainer` after erase events.
- Erase actions should participate in undo/redo if practical.

### 8. Undo / Redo

- Add an `UndoRedoService`.
- Track completed actions:
  - add stroke
  - erase stroke(s)
- Undo removes the latest completed annotation action.
- Redo restores the latest undone action.
- Clear redo stack after a new action.
- Disable or visually inactive-state `Undo` when no undo action exists.
- Disable or visually inactive-state `Redo` when no redo action exists.
- Keep native `InkCanvas` contents and `AnnotationDocument` model synchronized after every undo/redo.

### 9. Pointer Diagnostics

- Listen for pointer entered/moved/pressed/released events on each page annotation layer.
- Update debug text with useful details, for example:

  ```text
  pointer: pen | pressure: 0.42 | mode: ink | page: 3
  ```

- Include at least:
  - pointer type: mouse / pen / touch / unknown
  - mode: ink / eraser
  - page number
  - pressure if available
- Stroke count should reflect the current stored annotation strokes after add, erase, undo, and redo.

## Test Plan

- Unit tests:
  - adding strokes updates stroke count.
  - strokes are grouped by correct page number.
  - undo removes latest stroke.
  - redo restores undone stroke.
  - erase action removes expected stroke(s).
  - new action clears redo stack.
- Build validation:
  - solution restores successfully.
  - app project builds.
  - test project runs.
- Manual app validation:
  - launch app and confirm empty state.
  - open a local PDF.
  - confirm filename is shown.
  - confirm pages render vertically and scroll.
  - draw on page 1 and another page; confirm stroke count changes.
  - erase a stroke.
  - undo and redo drawing.
  - undo and redo erase if implemented.
  - confirm touch scroll does not create ink.
  - confirm mouse/pen/touch diagnostics update.
  - test inverted stylus eraser if supported by available hardware.

## Assumptions

- Use `README.md` for the requested “create me” build/run/test document.
- Use native WinUI ink controls for the spike because palm rejection and stylus eraser behavior are core evaluation goals.
- Use in-memory annotations only; no save/load/export.
- Use black ink and fixed thickness only.
- A simple non-virtualized vertical page list is acceptable for the first spike, with a render-width cap to keep large PDFs usable.
- If exact inverted eraser detection is not exposed by the available WinUI APIs or hardware, the app should still provide manual eraser mode and document the limitation in `ARCHITECTURE.md`.
